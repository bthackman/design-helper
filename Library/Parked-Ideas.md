# Parked ideas register (cross-project)

The `Library/` folders above promote *winners* — moves and materials that worked. This registers
the opposite: things that got killed, and why, so a future project can search "has this been tried
before, anywhere" and get an honest answer instead of re-litigating a dead idea from scratch.

This is the same convention the tool already applies within one project — a demoted driver or a
parked/dead massing option is kept on record rather than deleted, "recoverable when the client asks
'did you consider...?'" — just extended past the project boundary it currently stops at. A rejection
that only lives in one project's decision log is invisible to every other project.

**Log here at the phase gate**, alongside (not instead of) the per-project record:
- A **demoted, reframed, or dropped driver** (phase 0 — see `phase-0-drivers.md`'s "full disposition" gate)
- A **parked or dead massing option** (phase 3 — see `phase-3-massing.md`'s "Converge" step)
- A **cut site zone or parcel** (phase 2 — see `phase-2-site.md`'s "Site search" scoring)

One row per idea. Keep it terse — this is an index to go find the real reasoning in that project's
own decision log, not a duplicate of it.

**Tags** are what make this searchable later — reuse tags across entries rather than coining a new
one per row (e.g. `budget`, `zoning-conflict`, `client-vetoed`, `daylight-lost`, `too-precedent-y`,
`site-couldn't-support`). If a tag shows up often, that's worth a conversation on its own — a pattern
of dead ideas sharing a cause is itself a finding.
