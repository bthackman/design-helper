# Design Process Tool — Concept Spec (v0.1)

*Ben Hackman · July 2026 · Draft for reaction*

## What it is

A personal design copilot that walks a project from precedent discovery → site design → building massing → space planning → materiality. It guides each phase, captures what's found and decided, generates options and critique with AI, and keeps a decision trail so early thinking survives to later phases. Every project also feeds a growing cross-project library of precedents, site strategies, and materials.

**User:** Ben. **Typology:** agnostic. **Starting input:** a client brief/program, even rough. **Software relationship:** lives alongside Rhino/Revit; exports program tables, area schedules, and briefs.

## Core structure: five phases + a spine

Phases run in rough order but loop freely — a massing idea can send you back to precedent hunting. What makes looping safe is the **project spine**: a persistent record that every phase reads from and writes to.

The spine holds four things:

1. **Brief** — the program as understood *now* (spaces, areas, adjacencies, constraints). Living document, versioned.
2. **Design drivers** — the 3–7 big ideas steering the project (e.g. "daylight to every workspace," "civic face to the street"). Each phase tests its output against these.
3. **Decision log** — every significant decision: what, why, what was rejected, which phase, date.
4. **Open questions** — unresolved items that carry between phases so nothing is silently dropped.

## The five phases

| Phase | Guides you through | Captures | AI assists by | Output |
|---|---|---|---|---|
| 1. Precedents | Framing what you're actually looking for (typology, scale, climate, parti, material era) before searching | Tagged precedent cards: image, architect, why it's relevant, what to steal | Web research: finds built work matched to brief + drivers; summarizes and tags | Precedent board + "lessons" list |
| 2. Site | Context, climate, zoning/setbacks, access, views, topography, neighbours | Site facts + constraints map; opportunities/threats | Interrogates site data; suggests site strategies (orientation, entry, massing zones) | Site strategy: diagram + rationale notes |
| 3. Massing | Generating 3+ distinct options; testing each vs. drivers, zoning envelope, gross area | Option cards: sketch/image, GFA, storeys, pros/cons vs. drivers | Proposes parti/massing strategies to react to; critiques options; math-checks FAR/GFA | 2–3 massing options + recommended direction w/ rationale |
| 4. Space planning | Program-vs-area test fits; adjacency compliance; grossing factors; stacking | Program table (space, count, NSF, floor), adjacency matrix, stacking diagram | Stress-tests brief (gaps, unrealistic areas, missing support space); checks fit vs. massing GFA | Test fit + reconciled program table (→ export to Revit/Excel) |
| 5. Materiality | Palette by system (envelope, structure, interior); performance, cost tier, carbon; precedent tie-back | Material cards: image, application, why, precedent link | Suggests palettes matched to drivers + budget; flags durability/climate mismatches | Material palette board + spec-level notes |

**Phase-gate ritual (lightweight):** before moving on, the AI acts as critic — "Does this output serve the drivers? What's undecided? What would a skeptical PM ask?" Answers go to the decision log and open questions.

## Data model (what gets stored)

- **Project** → has one Brief, Drivers, Decision Log, Open Questions
- **Precedent** (belongs to project, copied to Library) — image, source, tags, lessons
- **Site fact / constraint** — category, value, source, implication
- **Massing option** — image, metrics, driver scorecard, status (active/parked/dead)
- **Space** — name, count, NSF, adjacencies, floor assignment
- **Material** — name, system, application, rationale, precedent link
- **Decision** — statement, rationale, alternatives rejected, phase, date
- **Library** (cross-project) — precedents, site strategies, materials, promoted from projects with tags

## Exports (light data exchange)

- Program table / area schedule → Excel (Revit-importable format)
- Brief + drivers → Word/PDF for client alignment
- Precedent and material boards → PDF
- Decision log → running Word doc for project record

## Build path

**v0 — this Claude project as the tool (start here, this week).** Folder structure + markdown templates in this project folder; a custom skill ("design-process") that knows the five phases, runs the guided prompts, does AI research/critique, and writes to the templates. Zero software to build; validates the process on a real project.

**v1 — structured database.** Once v0 shows which records matter, move the data model to Airtable (already connected): linked tables, gallery views for precedent/material boards, grid views for program tables. Claude still drives the process; Airtable holds the state.

**v2 — dedicated web app.** Only if v1 hits limits: custom UI per phase, board layouts, Rhino/Revit data exchange via API.
